# Правила для агентов — url-shortener-golang

Этот репозиторий ведёт Dayforge: агенты разрабатывают проект по плану, по одной задаче за сессию. Правила ниже обязательны для любой сессии.

## Документы

| Файл | Что это | Кто меняет |
|---|---|---|
| `docs/IDEA.md` | Исходная идея и ответы пользователя на уточняющие вопросы | Система |
| `docs/ARCHITECTURE.md` | Стек, модули, ключевые решения, как запускать тесты | Планировщик; исполнитель — при значимых решениях |
| `docs/PLAN.md` | План по дням, статусы задач, вехи | **Только система** — не редактировать |
| `docs/JOURNAL.md` | Журнал: что сделано, какие решения приняты и почему | Исполнитель |

## Git

- Работай **только в текущей ветке**. Не переключай ветки, не мержи, не пушь, не переписывай историю — этим занимается система.
- Коммиты — Conventional Commits с ключом задачи: `feat(T12): …`, `test(T12): …`, `fix(T12): …`.
- Перед паузой (после `ask_user` или `request_secret`) закоммить текущую работу: `wip(T12): <почему пауза>`.

## Работа над задачей

- Задача, её критерии готовности и команда тестов приходят в стартовом сообщении сессии.
- Пиши тесты к тому, что делаешь; перед завершением прогони команду тестов — система прогонит её ещё раз перед мержем.
- Вопросы, которые можешь решить сам, решай сам и записывай решение в `docs/JOURNAL.md`.
- Спрашивай пользователя (`ask_user`) только то, без чего продолжать нельзя.
- Закончи сессию одним из вызовов: `complete_task`, `ask_user`, `request_secret`, `fail_task`.

## Секреты

Секреты лежат в `.env` в корне репозитория (он в `.gitignore`). Не коммить их и не выводи в логи. Нужен новый — `request_secret`.
